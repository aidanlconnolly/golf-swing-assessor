# Golf Swing Assessor

Side-by-side golf swing analyzer. Upload two swing videos, compare them frame-by-frame with synchronized playback, overlay a live MediaPipe pose skeleton, and get automatic flaw detection at the key swing positions.

## Stack
Single-file vanilla HTML/CSS/JS, no build step. Pose detection uses **MediaPipe Tasks Vision** (`@mediapipe/tasks-vision`) loaded from the jsDelivr CDN via dynamic `import()` inside the module script; the `pose_landmarker_lite` model is fetched from Google's model storage. The script tag is `type="module"`. Everything runs **entirely client-side** — there is no backend and no Anthropic/API key; the only network traffic is the one-time CDN download of the library + model (works offline after that).

## Run locally
MediaPipe (Phase 2) needs the page served over HTTP, so run a static server rather than opening the file directly:
```bash
cd "Golf swing assessor" && python3 -m http.server 5800
```
Then open http://localhost:5800 . Preview entry: `golf-swing` (port 5800) in the workspace `.claude/launch.json`.

## Structure
Everything lives in `index.html`:
- **Transport bar** — a single control bar (`.transport`) pinned at the top of the page (`position: sticky`) *above* the two videos. Holds the scrubber + time readout, play/restart/frame-step buttons, the **View** focus toggle (Both / Swing A / Swing B), speed buttons, the **Skeleton** + **Guides** overlay toggles + pose-load status, the camera-view `<select>` (Auto / Face-on / Down-the-line), the handedness `<select>`, and the **Detect flaws** / **Compare swings** / **Save image** buttons.
- **`Lane` class** — one per video column; owns its `<video>`, `<canvas>` overlay (`this.canvas`), dropzone, file input, drag/drop + click-to-browse, and `loadedmetadata` wiring. On metadata load it sets `stage.style.aspectRatio` to the video's real `vw/vh` so portrait phone clips fill the frame instead of a tiny 16:9 letterbox (stage is height-capped via `max-height`).
- **Sync controller** — module-level functions (`play`/`pause`/`restart`/`stepBy`/`seekFraction`/`setSpeed`) that act on the lanes returned by `controlLanes()`. A **focus mode** (`focusLane`, set via the View: Both/Swing A/Swing B buttons and `setFocus()`) narrows the transport to a single enlarged lane; in "Both" it drives every loaded lane at once. The scrubber/time readout (`maxDuration`/`masterTime`) follow `controlLanes()`, so a focused lane shows *its own* clock. Clicking a flaw/timeline chip calls `seekLaneTo()` which focuses that lane first (fixes the timestamp readout mismatch). In "Both" mode `play()` rewinds every controlled lane to the start when either clip has ended or the two have drifted out of sync, so the swings always play together from address. Playback stops when all controlled lanes reach their end (no looping).
- **`tick()`** — `requestAnimationFrame` loop that keeps the scrubber + time readout in sync.
- **Pose overlay (Phase 2)** — `setupPose()` creates one `PoseLandmarker` (VIDEO mode) per lane sharing a single `FilesetResolver` (kept in `_vision`/`_PoseLandmarker` for reuse). `attachOverlay()` drives detection off `video.requestVideoFrameCallback` during playback, plus `seeked`/`loadeddata` listeners so the skeleton updates while frame-stepping/scrubbing paused. Detection now runs whenever **either** the skeleton (`overlayOn`) **or** Guides (`guidesOn`) is active. `drawPose()` maps the 33 normalized BlazePose landmarks onto the letterboxed (object-fit: contain) video rect: it draws **reference guides** first (`drawStaticGuides()` = the amber hand-path arc + dashed head-still line built by `buildGuides()` after analysis; `drawSpine()` = the live hip→shoulder spine line) when `guidesOn`, then — only when `overlayOn` — the skeleton connectors + dots, with `KEY_JOINTS` (shoulders/elbows/wrists/hips/knees) highlighted and `lane.flaggedJoints` drawn red. GPU delegate with CPU fallback. Detection timestamps are forced monotonic per lane.
- **Flaw analysis (Phase 3)** — `analyzeAll()` lazily creates a separate IMAGE-mode `analysisLandmarker`, then for each loaded lane `captureFrames()` scrubs the clip frame-by-frame (`seekTo` resolves immediately if already at `t`, else awaits `seeked` with an 800ms safety timeout; capped at 150 frames; reports a `frame n/total` progress count) and buffers `{t, lm}`. Captures are **cached by `lane.framesUrl`** so re-analysis (e.g. after changing handedness/view) skips the slow re-seek. `detectEvents()` finds address/top/impact/follow-through from a **3-tap-smoothed** wrist-midpoint trajectory + speed. **Camera view** — `inferView()` estimates Face-on vs Down-the-line from projected shoulder-width ÷ `bodyScale`; `effectiveView()` returns the user's `<select>` choice or that auto value. `detectFlaws()` applies ~16 pose-only heuristics, each tagged with a `view` (`'face'`/`'dtl'`/`'both'`) and **filtered to the active view** so depth-axis faults (sway, weight-shift, head-ahead) only fire face-on and plane faults (over-the-top, flying elbow) only down-the-line — cutting false positives. Heuristics are normalized by `bodyScale` (shoulder-center→hip-center distance), gated on landmark visibility, and oriented by a `targetDir` inferred from hand travel (top→follow); the `SIDE` table maps lead/trail joints from the handedness `<select>`. `trackingQuality()` flags low-confidence captures. `computeMetrics()` derives backswing/downswing times + tempo ratio. `renderResults()` builds per-lane cards (view label + tracking-quality warning, clickable timeline chips, severity-colored flaw rows that seek the lane and set `flaggedJoints` red). `renderCompare()` / **Compare swings** button (`compareSwings()`) analyzes both lanes, switches to Both view lined up at address, and renders a metric/fault comparison table (`#compare`) highlighting the better column + shared faults. `exportImage()` / **Save image** renders the per-swing findings to a canvas and downloads a PNG. **These are estimates — the club is not tracked and a single uncalibrated camera angle limits accuracy.**

Frame stepping assumes `FPS = 30` (`STEP = 1/FPS`). Adjust `FPS` if real per-frame stepping is needed for known footage.
